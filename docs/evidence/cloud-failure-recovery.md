# Failure and recovery evidence

The local automated integration test `test_local_ingest_idempotence_and_quarantine` exercises a valid batch, a malformed JSONL batch, a deterministic retry, and a retained quarantine report. It passed in the local test run.

Cloud smoke result (2026-11-06 UTC): after repairing the Linux Lambda package, re-uploading an identical synthetic placement batch left the curated ETag unchanged. A one-row synthetic batch with `freight_brl = -1` produced a 345-byte quarantine report under the project's `quarantine/` prefix and no curated counterpart. CloudWatch logged the redacted batch ID, `quarantined` status, and validation reason. The original Windows-package import failure was repaired by rebuilding with manylinux wheels and applying one in-place Lambda code update.

Stage 100 recovery result (2026-11-06 UTC): the newly added immutable curated-object check first exposed a least-privilege gap: Lambda could write `curated/*` but could not read a missing curated key. Terraform then applied a one-policy in-place change granting `GetObject` for `curated/*` and `ListBucket` only when `s3:prefix` matches `curated/*`. Retrying the same two raw objects produced the expected curated objects. A further identical retry left both curated ETags unchanged and Lambda logged `duplicate` for the 100-placement and 86-outcome batches. No Stage 100 quarantine object exists.

Full-run recovery result (2026-11-06 UTC): the initial client upload stopped after 964 placement raw objects. A read-only inventory showed the local manifest remained complete and no quarantine/error evidence existed. `s3 sync --dryrun --size-only` identified exactly 23 missing placement and 964 missing outcome objects; the subsequent size-only sync uploaded only those missing keys without replacing the existing 964 raw objects. Final raw and curated inventories were 987 placement plus 964 outcome objects, with zero quarantine. This preserves deterministic batch keys and auditability while recovering an interrupted client-side upload.
